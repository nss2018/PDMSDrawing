一、A 做了什么

1. 根因与层级定案

2026-10-17「SYTM 建库失败」不是 API 不行，是父级挂错世界。本机旧日志实证三次失败全在 DEPT.CreateLast(LALB)；而 14p（11-08）已证 WORLD → LIBY → RPLB → STYL 四级可建。 AVEVA Draft 官方文档写明：SYTM 是 Library sheet 上的 2D drafting 元素集合，SYLB / LALB 视为 sheet， 必须挂在 LIBY 下；SLAB / SYMB 的 TMRF 指向 SYTM 即在 SHEET 上渲染。 所以正解是 DEPT/REGI → LIBY → SYLB → SYTM（LALB 承载 TXTM，历史上把 SYTM 挂 LALB 也是错的）。

二、B 怎么做：让 PDMS 原生视图自动出图例

B 的目标是：不再靠 replace_symbols 后画，而是 UPDATE ALL 时 PDMS 自己按元件类型/CATREF 把符号生成到视图里。官方叫 2D Symbolic Representation，链路是「Draft 符号模板 → Paragon 元件库链接 → Draft 表示规则 → DESSYM」。 A 建好的 13 个 SYTM 正好是它的第 1 环。

1. 完整链路（官方案例 + 本项目 RRSF 实证）

阶段模块 / 层级要设的属性说明
① 模板Draft DEPT > REGI > LIBY > SYLB > SYTM—A 已做（13 个模板）
② 符号链接Paragon CATA > SECT > DRSSET > DRSYLKDrTmpref → SYTM；Criteria按元件类型/口径挑该用哪个模板；一个 DRSSET 管一组
③ 通用部件Paragon PRTWLD > PRTELE > GPARTTmpref、DrSSRef（→ DRSSET）把符号链接挂到通用部件
④ 等级元件SPWL > SPEC > SELE > SPCOPrtref（→ GPART）、Tmpref或走 TABGRO > CTABLE > TABITE
⑤ 设计元件Design SITE > ZONE > EQUI（标准设备）Spref → SPEC管道元件靠 CATR/SPREF，规则按此认
⑥ 表示规则Draft DRWG > SHEE > VIEW > RRULStyf=Nulref、Omitflag=false、SymbolFlag=true、Criteria一个 2D 符号一条 RRUL；本项目 RRSF 指向 /DRA/PRJ/...
⑦ 生成VIEW 上 Graphics > Update > All—自动建 DSLAYE，其下 DESSYM 每个代表一个 SYTM/TXTM
⑧ 微调DESSYMADEG / BLNK / XYSCALE / XYPOS方向、消隐、缩放、位置

2. 官方明确的三条硬限制

  • 符号方向不跟随 EQUI 方向——要改 DESSYM 的 ADEG；本项目阀门/弯头方向由管线走向算，仍需代码/规则补。
  • DESSYM 不能智能标注（尺寸、GLAB、SLAB 都认不了）→ 官方案例建议用 Local Rules (RULL) 在智能标注完成后再应用 2D 符号。
  • 没有合法 CATREF / SPREF 的裸元件规则认不出——本项目 14x/15a 已实证大量裸 BRANCH/测点，这部分永远需要代码兜底。

3. 本项目特有的坑（不是文档上的，是这台机器上踩过的）

  • PRJ / MAS 库拒写：14n/14p 两次实测 /DRA/PRJ/STYL/PIPE/CLINE 的 CLSTYL 属性 IsAttributeSetable=false， 14p 才被迫在 WORLD 下自建 LIBY AGT_LIB → RPLB AGT_STYLIB 克隆样式并重指向 RRUL 成员。 B 配 RRUL 大概率也要走「自建可写规则库 + 重指向」，不能直接改项目模板库。
  • UPDATE ALL 是全局动作：规则 Criteria 写错会全项目渲染空白；必须先建测试库、先 SAVEWORK、先在单张图上验。
  • 会碰 15f 刚修好的链路：贴线标注依赖 pendStrokes（13n 可见段收集）。B 改了视图生成内容后， 要重新确认 (14u) 命中N 与 (15f) 不引出 没被 UPDATE 行为带偏。

4. 建议的分阶段实施（每阶段带门禁）

阶段动作门禁（不过就停）
P0备份项目库 + 建测试 DRAFT 库/测试图；确认 DRAFTADMIN 权限能在测试库里 UPDATE ALL 且不报错
P1用 A 的 13 个 SYTM，在 Paragon 建 DRSSET/DRSYLK，逐条填 DrTmpref + Criteria13 条 DrTmpref 回读全部指向存在的 SYTM

P3在自建可写规则库里建 RRUL（SymbolFlag=true），把 VIEW.RRSF 临时切过去，UPDATE ALL生成 DSLAYE + DESSYM 且截图里符号可见、方向正确
P4按类型灰度关掉 replace_symbols 的自绘（先法兰→弯头→三通→阀门），无 CATREF 裸元件保留代码兜底DXF 里符号数量与元件数对得上，且无重复/无空白

5. 结论与建议

B 技术上可行，但它是「改项目库 + 改表示规则」的项目级改造，影响面远超 A： 规则配错全项目渲染空白、PRJ/MAS 拒写要绕、DESSYM 不可智能标注、裸元件永远要代码兜底。 因此建议顺序：先把 A 跑通并截图确认库符号渲染正常 → 再进 B 的 P0/P1（P0/P1 只加链接、不改视图行为，是可逆的）； P3 往后每步都在测试库做 + SAVEWORK。B 的终点也不是「replace_symbols 删掉」，而是 「原生规则负责绝大部分标准元件，代码只兜底裸元件与标注」。本轮未动任何数据库、未配任何 RRUL。
