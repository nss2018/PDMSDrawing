一、管线号：为什么全被引出去了

1. 现象（本轮 09:08 出图 + 离线 DXF 复核）

  • 截图里 93 个菱形管线号沿图框上下边排成两带，一堆红色长引线斜穿设备区。
  • DXF 统计：菱形 y 集中在 100~180 与 670~730 两带；x 集中在 550~750，是典型「视图四边成排」落位，不是贴线。

归属段 0/0 = pendStrokes 整个可见段表是空的。14u/14w/14x/14y 这一整条贴线链路全在空转，之前 14w「罚分打分」、14x「幽灵序号」、14y「锚点吸附」调的都是一条没有输入的通道。

3. 根因：13n 页框索引错位（11-05 引入，潜伏至今）

drawE3DTool.ParseLimitsString 对 From W… N… U… To W… N… U… 实际返回 [Wfrom, Nfrom, Ufrom, Wto, Nto, Uto]，但函数注释写的是 [xmin,xmax,ymin,ymax,zmin,zmax]。13n 照注释取索引：

旧：pageBox = { lb[0]-mg, lb[2]-mg, 0, lb[1]+mg, lb[3]+mg, 0 }
 → W1878552  N-4900  TO W1594600  N1904422   （xmin > xmax，框倒置）
判据 bb[0] > pageBox[3] 恒真 → 281 条 BRANCH 全部被剔除

连锁反应：无 BRANCH → 无 strokes → pendStrokes=0 → 贴线无候选 → 93 个编号全走 9e 旧环 → PlaceEscort 把菱形推到图框边 → 每条画一根长引线。截图里那一堆乱红线就是这么来的。

二、图例替换：能不能在数据库里完成

1. 结论：机制上能，但这台机器的库是空的

09:06:52 出图日志的「符号模板体检」实锤：

/TT/Isometric_ADP/Arrow1     => 缺失(渲染空白)
/TT/Isometric_ADP/Flan       => 缺失(渲染空白)
/MDS/ABA/TAGS/ELBO           => 缺失(渲染空白)
/MDS/ABA/TAGS/ELBO--UP       => 缺失(渲染空白)
/MDS/ABA/TAGS/Valv-H / Valv-V=> 缺失(渲染空白)
/MDS/ABA/TAGS/CIRCLE/2       => 存在 type=SYTM
/TT/DRA/MAS/LABELS/GEN/PIPE/END => 存在 type=SYTM

PDMS 原生视图要按元件类型套图例，靠的是 SYTM（Symbol Template）符号库 + 表示规则。这俩模板库基本没装，所以 UPDATE all 出不来图例。现在 replace_symbols 每次画 弯头77 / 阀门71 / 法兰127 / 三通107（约 9200 条命令）把符号补上去——用户圈出来的那几处红色小图例，就是这么后画出来的，不是库里带出来的。15c 那个阀门按管径缩放，本质就是在给「代码推算的符号尺寸」打补丁。

2. 为什么以前没能建库（已排除）

历史结论是「SYTM 建库失败」：SymBlocks.cs 头注释实锤，SYTM/LALB 属 LIBRARY 世界，当年挂在 DRAFT 世界的 DEPT 下，CreateLast 一律抛「应用程序中的错误」。但 14p 已经证明 LIBY → RPLB → STYL 四级链路可建（线型样式库就是这么建的），所以「在库里配符号」这条路是通的，只是父级挂错了世界。

3. 两条实施路线

路线做什么收益代价 / 风险
A 折中（推荐先做）在 LIBY 世界下一次性建 13 个 SYTM（阀门/截止阀/弯头上下翻/三通/法兰/盲板/焊点/异径管/管架/箭头）；replace_symbols 由「画 9200 条 STRAIGHT」改为「插入 SLABEL 引用 SYTM」图例几何真正从库里来，改样式只改库不用重编译；位置/朝向仍由代码按真实元件定位，效果可控中等；需 SAVEWORK 落库，先做符号库不影响既有图纸
B 彻底A + 配 Draft 表示规则（RULB/ADET 的 SYMBOL 引用）或 Paragon 元件库 SCOM 的符号引用（DTREF/DSYMBOL），让 UPDATE all 自动按 CATREF 出图例不用再跑 replace_symbols 的符号段；全项目所有图纸自动统一，符号大小/朝向由 PDMS 按真实几何与比例算大；改项目库影响面广，规则配错会全项目渲染空白，须测试库先做

4. 三个必须说清的限制

  • 裸元件认不出：没有合法 CATREF 的元件（本项目里有一部分），表示规则匹配不上，仍会渲染空白，得保留代码兜底。
  • 模板库随项目走：/MDS/ABA/TAGS 这类是项目模板，换电脑/换项目就没了——这正是当年改自绘的原因；自建 /AGT_SYMS 库才能随部署走。
  • 不是「替换」而是「出图时自动带出」：数据库配置解决的是「符号从哪来」，解决不了「这张图上已有图形怎么就地改写」；后者仍是后处理。

建议：先做 A（补 13 个 SYTM + 代码改引用），验证符号一致后再评估要不要上 B 的表示规则。改库属于项目级动作，已留给用户拍板，本轮没有动任何数据库。
