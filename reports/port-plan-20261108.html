PDMS 桥端口分配表

2026-11-08 定稿 · 原则：两族分开、每个启动脚本一个专属口、不共用不靠顺延抢

端口分族（零重叠）

18753 – 18762绘图桥族 · drawingPDMS / PdmsBridge
18763 – 18783支架桥族 · SupportBridge
1875318762│1876318783
  • 绘图桥族不设任何环境变量覆盖：保留 MCP 默认 18753 / paragon 18754，drawingPDMS 内嵌桥被占时最多 +9 顺延到 18762，永远出不了这一族。
  • 支架桥族每个脚本一个固定口：SupportBridge 的顺延（+20）也只在本族内，不会掉回 18753。
  • 两族之间留 18762 / 18763 一条硬边界，support_hello 身份校验仍作为双保险。

根因与配套改动

  • 根因：pdms - SWX(Para) .bat（11-02 21:56 建）写了 set SUPPORT_BRIDGE_PORT=18753，把支架桥拽到绘图桥主口。HKCU/HKLM 无此变量，全机唯一覆盖源。部署 DLL 默认其实已是 18763（IL ldc.i4 18763 实证），11-05 源码也改了默认 —— bat 漏改才拖到 11-08 爆。
  • PdmsDrawStudio：FindDrawingBridge 扫描收窄为 18753–18763（原 18753–18770），默认图型改「管道布置图」，每个 op 前用 support_hello 自动认绘图桥（14e）。
  • SupportStudio：扫描扩为 18763–18783（原只扫 18763），清理 18753/18754/18755 过时文案。
  • 发布：两 EXE dotnet publish -c Release 零错误；PdmsDrawStudio 同步到 publish_14m，SupportStudio 旧版备份 .bak-20261108。IL 校验：绘图 EXE 已无 18770，支架 EXE 有 18783。
  • 校验：4 个脚本端口零重复、无一落入绘图族、无残留 set PDMS_BRIDGE_PORT。pdms.bat 一次只拉一个模块，脚本层分口即够，无需重编译桥 DLL。
生效条件：改 bat 只对下次启动生效。当前 PDMS（pid 20648）仍占着 18753 的旧支架桥 —— 必须关掉重启 PDMS，再开新 EXE 出一版验证。实机效果未验证。
