# PdmsBridge 独立 Addin — 部署说明（档位② · 行位②）

> 本目录是一个**自包含**的 .NET Framework 3.5 工程，编译出一个 PDMS Addin：
> PDMS 启动时自动在 `127.0.0.1:18753` 起一个 TCP 监听器，供 pdms-bridge 的 MCP 服务端驱动。

## 1. 编译

1. 用 VS 打开 `PdmsBridge.csproj`（或 `msbuild PdmsBridge.csproj`）。
2. 目标框架：**.NET Framework 3.5**；平台：**AnyCPU**（⚠️ 切勿 x64：PDMS 12.1 宿主 `des.exe` 是 **32 位**进程，x64 程序集无法加载，AddinManager 静默跳过 → 桥永远不启动。2026-10-19 事故根因）。
3. 引用（HintPath 已按 `C:\AVEVA\Plant\PDMS12.1.SP4\` 填好，换机请改）：

   | 引用 | 本机文件 | 作用 |
   |---|---|---|
   | `Aveva.ApplicationFramework` | `Aveva.ApplicationFramework.dll` | **`IAddin` 接口在这里** |
   | `Aveva.Pdms.Database` | `Aveva.Pdms.Database.dll` | 数据库访问 |
   | `Aveva.Pdms.Utilities` | `Aveva.Pdms.Utilities.dll` | `Command.RunInPdms` |

   > ⚠️ 网上很多范例写 `Aveva.Pdms.Addins.dll` —— **本机没有这个文件**，
   > `IAddin` 实际定义在 `Aveva.ApplicationFramework.dll`（命名空间 `Aveva.ApplicationFramework`）。

4. 编译产物：`bin\Debug\PdmsBridge.dll`。

## 2. 部署

1. 把 `PdmsBridge.dll` 拷到 PDMS 安装目录**根**：
   `C:\AVEVA\Plant\PDMS12.1.SP4\`（与你现有 `FangYuanPDMS.dll` 同级）。

## 3. 注册（关键：PDMS 12.1 用 `*Addins.xml`，**不是** `.addin` 文件）

PDMS 12.1 的 Addin 清单是安装目录下的几个 `ArrayOfString` XML：

- `DesignAddins.xml`
- `DraftAddins.xml`
- `AdminAddins.xml`
- `IsodraftAddins.xml`

在需要的模块清单里**追加一行**（插件名要与 `PdmsBridgeAddin.Name` 返回的字符串一致）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<ArrayOfString xmlns:xsd="http://www.w3.org/2001/XMLSchema"
               xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <!-- ...原有条目... -->
  <string>PdmsBridge</string>
</ArrayOfString>
```

> 若加载不生效，可再补一行 `<string>PdmsBridgeAddin</string>`（部分版本按类型名匹配）。
> 改前请先备份原 `*Addins.xml`。

## 4. 验证

1. 启动 PDMS（任意模块）。
2. 查看 `C:\pdmsAgent\bridge\bridge.log`，应出现：
   `... PdmsBridge started on 127.0.0.1:18753`
3. 起 MCP 服务端并自检：
   ```
   node ..\..\..\server.js          # 或在 mcp.json 里已注册的 pdms-bridge
   ```
   调用 `pdms_status` 应返回 `connected: true`。

## 文件清单

| 文件 | 说明 |
|---|---|
| `PdmsBridge.cs` | 监听器本体（**自包含副本**，与 `assets\PdmsBridge.cs` 同步） |

| `PdmsBridge.csproj` | 工程文件（自包含，含正确的 PDMS 引用） |
