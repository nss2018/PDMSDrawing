# pdms-bridge 连机方案（Connection Guide）

> 本文用**资料库「PDMS·E3D 私有资料库」里的官方文档**（`PDMS and Associated Products Installation Guide.pdf` §4.6/§4.7、`PDMS User Bulletin.pdf` §5.1、`PDMS 二次开发，中级，高级.pdf`）把 bridge 的"怎么连上真机 PDMS"补全成可执行的方案。
>
> 结论先行：**之前连不上，不是因为没装 PDMS（PDMS 就在这台机器 `C:\AVEVA\Plant\PDMS12.1.SP4\`），而是 bridge 的工程假设与真机不一致 + 一条死通道。** 三条真因见 §1。

## 2. PDMS 自动化三件套（资料库原文依据）

### 2.1 TTY 模式（无 GUI 命令行）
> *Installation Guide §4.6.1*：`C:\AVEVA\Plant\PDMS12.1.SP4\pdms.bat TTY SAM SYSTEM/XXXXXX /STRUC $M/mymacrofile`
> - `TTY` = 不启动 GUI，纯命令行运行
> - `SAM` = 项目名；`SYSTEM/XXXXXX` = 用户名/密码；`/STRUC` = 选 MDB；`$M/mymacrofile` = 要跑的宏
> - 本机实测 `pdms.bat` 会把 `%2 %3…` 透传给 `mon.exe/des.exe`，故 `TTY` 等参数确实生效。

### 2.2 PDMSConsole 进程 + PDMSWait + PDMS_CONSOLE_IDENTIFIER
> *Installation Guide §4.7*：PDMS 会起一个独立的 **`PDMSConsole` 进程**统一管理所有模块的命令行输入/输出。`.bat` 里 PDMS 离开 MONITOR 后脚本会继续跑（PDMS 还在跑）。用随 PDMS 发布的 **`PDMSWait.exe`** 等它结束。`PDMSWait`/`PDMSConsole` 都看环境变量 **`PDMS_CONSOLE_IDENTIFIER`** 来区分多会话——`.bat` 里用 `%RANDOM%` 即可：
> ```bat
> set PDMS_CONSOLE_IDENTIFIER=%RANDOM%
> call %PDMSEXE%\pdms
> call %PDMSEXE%\pdmswait
> ```

### 2.3 GUI + 控制台窗口（交互式，但 WorkBuddy 接不进去）
> *User Bulletin §5.1*：PDMS 12 起界面基于 .NET/WinForms；可用 `-noconsole` 或 `AVEVA_NOCONsole=TRUE` 隐藏控制台。
> 关键点：**GUI 模式的控制台是 PDMS 自己的窗口，WorkBuddy 无法把命令喂进它的 stdin**。所以"智能体实时驱动 PDMS"不能靠直连控制台，必须靠下面 §3 的桥。

### 2.4 本机实测：TTY 无头模式确实能打开 PDMS 并登录 Monitor（2026-10-15）

> 用本机真实 PDMS 跑通，**直接证明"能打开"**，也验证了 §3 档位③ 的可行性。

**命令（经 PowerShell 启动，见下方"启动要点"）：**
```
pdms.bat TTY Master SYSTEM/XXXXXX
# stdin 喂： SHOW MODULE  ↵  QUIT  ↵
```

**真实输出（节选）：**
```
running: C:\AVEVA\Plant\PDMS12.1.SP4\mon TTY  Master SYSTEM/XXXXXX
This version was issued to your company
and will only operate on registered hardware
AVEVA PDMS Monitor Mk12.1.SP4.51[6776]  (WINDOWS-NT 6.3)  (18 Dec 2018 : 04:22)
Copyright 1974 to current year.  AVEVA Solutions Limited and its subsidiaries. All rights reserved.

Non Graphics Device (Appware will not be loaded).
* SHOW MODULE
(47,15)   CP: Syntax error        ← 命令被真实解析执行（MONITOR 不支持该语法，但证明命令通道工作）
* QUIT
```

**结论：**
- ✅ PDMS **能打开**；`mon.exe` 启动后进入 **PDMS Monitor** 模块，`Non Graphics Device` 确认是无头。
- ✅ 登录成功（无登录失败提示，直接进 Monitor 命令行 `* `）。
- ✅ 命令被真实下发并解析（`SHOW MODULE` 报 `CP: Syntax error` 说明 CP 命令通道工作；该语法错误只是因为 MONITOR 模块不支持 `SHOW MODULE`，真正出图命令在 Design/Draft 模块里）。
- ✅ `QUIT` + stdin EOF 后进程**干净退出**，无孤儿进程。

**启动要点（绕开本机 WorkBuddy 安全策略 / 环境变量冲突）：**
- 本机策略**禁** `cmd.exe`（Bash/PowerShell 调用都被拦）、**禁** `Add-Type`（运行时编译 .NET）、**禁** `New-Object System.Diagnostics.Process`。
- 且每次 PowerShell 命令会重新注入 `PATH` 环境变量，与已有的 `Path` 形成大小写重复键，导致 `Start-Process` 在构建子进程环境时抛 `已添加项。字典中的关键字:"Path"..."PATH"` 而失败。
- 可行配方（**必须在同一条命令内先删键再启动**，因为命令间策略会重新注入）：
  1. `[System.Environment]::SetEnvironmentVariable("PATH", $null)`（删除大小写重复键）
  2. `Start-Process pdms.bat -ArgumentList "TTY","Master","SYSTEM/XXXXXX" -RedirectStandardInput <命令文件> -RedirectStandardOutput <out> -RedirectStandardError <err>`
  3. 命令文件末尾写 `QUIT` 并 Close stdin，让 MONITOR 读 EOF 退出（否则会卡住成孤儿进程）。
- ⚠️ 注意：`master` 等项目的 `SYSTEM/XXXXXX` 是文档默认超级用户口令；若你们改过口令，换实际口令即可。

## 3. 连机方案三档（按"是否需编译 / 是否持久交互"分层）

```
                是否需要重编译 C# 插件？
               ┌──────────────┴──────────────┐
            否 │                             │ 是
   ┌───────────┴───────────┐       ┌─────────┴─────────┐
 零编译                      零编译·持久交互      需编译·最快最稳
 ┌──────────┐        ┌──────────────┐        ┌──────────────┐
 │ 档位3     │        │ 档位1         │        │ 档位2         │
 │ TTY 批处理│        │ PML2窗体轮询桥│        │ C# 独立Addin  │
 │ (慢/一次性)│        │ (复活file通道)│        │ TCP 监听      │
 └──────────┘        └──────────────┘        └──────────────┘
   适合夜间批量          适合交互式免编译            适合高频实时驱动
   (ISO百根管线等)        (临时演示/无VS环境)        (生产首选)
```

### 档位 1 — PML2 窗体定时轮询桥（零编译 · 持久交互）★推荐先试
**思路**：ROADMAP 说"裸命令宏无法轮询"是对的，但 `PDMS 二次开发，中级，高级.pdf` 第十章明确 **PML2 窗体（Forms）有 callback**。用 PML2 窗体的**定时回调（Timed Callback）**每 ~200ms 扫 `queue/` 目录，读到请求就 `$M` 执行并写 `done/` 结果文件。这样**完全不需要重编译任何 C#**，加载一个 `.pml` 即可获得持久交互通道。

- 启用：`PDMS_BRIDGE_TRANSPORT=file` + 在 PDMS 里 `$M AGENTBRIDGE`（宏见 `assets/pml/AGENTBRIDGE.PML`）。
- 优点：零编译、不掉 PDMS 会话、随开随用。
- ⚠️ 待你确认的一点：PML2 定时回调方法名（常见为 `addTimedCallback` / 窗体 `timedCallback` 事件）。若本机 PML 版本方法名不同，按窗体 callback 文档微调一行即可。
- 注：`server.js` 的 `callFile` 分支本就为它而写，只需把 §4 的路径改对即可复活。

### 档位 2 — C# 独立 Addin TCP（需编译 · 最快最稳）★生产首选
**思路**：把 `PdmsBridge.cs` 编译成**独立程序集 `PdmsBridge.dll`**，自带 `IAddin` 入口，部署到 PDMS 即可。无需改动你现有的 `FangYuanPDMS` 源码。

- 模板已备：`assets/mcp/addin/`（`PdmsBridge.cs` 改成中性命名空间 + `PdmsBridgeAddin.cs` 实现 `Aveva.Pdms.Addins.IAddin` + `PdmsBridge.addin` 清单 + `PdmsBridge.csproj`）。
- 框架：`.NET Framework 3.5 Client Profile`（与 `FangYuanPDMS.csproj` 的 `v3.5` 一致；**勿用 async/await、System.Text.Json、HttpClient**，PdmsBridge.cs 已规避）。
- 部署：拷贝 `PdmsBridge.dll` 到 PDMS 根目录（参考你 `FangYuanPDMS.dll` 的位置：`C:\AVEVA\Plant\PDMS12.1.SP4\`）；再把 `<string>PdmsBridge</string>` 追加进 `DesignAddins.xml` / `DraftAddins.xml` 等清单完成注册（PDMS 12.1 用 `*Addins.xml`，**不是** `.addin` 文件）。
- 启动 PDMS 后，监听器在 `127.0.0.1:18753` 自动起；`server.js` 默认 TCP 连它。

### 档位 3 — TTY 批处理（零编译 · 慢 · 一次性）
**思路**：每个任务启动一次 PDMS TTY 跑宏、读结果文件、退出。慢（每次几秒~十几秒启动），且每次是新会话（不保留上一次的状态/CE），**不适合交互式**，但适合**夜间批量**（如一次出 100 根管线的 ISO）。

- 模板：`assets/mcp/run_tty_task.bat`（已按 §2.1/§2.2 写好 `PDMS_CONSOLE_IDENTIFIER` + `pdmswait`）。
- 典型命令：
  ```bat
  set PDMS_CONSOLE_IDENTIFIER=%RANDOM%
  call "C:\AVEVA\Plant\PDMS12.1.SP4\pdms.bat" TTY <PROJECT> <USER>/<PASS> /<MDB> $M/C:/pdmsAgent/bridge/queue/<task>.pml
  call "%PDMSEXE%\pdmswait"
  ```

## 5. 分步实施（以档位 2 为主，档位 1 为快速验证）

### 步骤 A：准备桥工作目录
```bat
mkdir C:\pdmsAgent\bridge\queue
mkdir C:\pdmsAgent\bridge\done
```

### 步骤 B：部署插件（档位 2）
1. 用 VS / MSBuild 打开 `assets/mcp/addin/PdmsBridge.csproj`，引用 `C:\AVEVA\Plant\PDMS12.1.SP4\` 下的 `Aveva.Pdms.*.dll`、`Aveva.Pdms.Utilities.dll`、`Aveva.Pdms.Addins.dll`，以 **.NET 3.5** 编译出 `PdmsBridge.dll`。
2. 把 `PdmsBridge.dll` + `PdmsBridge.addin` 拷到 PDMS 插件目录（参考 `FangYuanPDMS.dll` 的位置）。
3. 启动 PDMS（任意模块）。监听器应自动在 18753 监听；查 `C:\pdmsAgent\bridge\bridge.log` 确认 `PdmsBridge started`。

> 若你的插件加载机制需要把 `Start()` 接到现有工程的入口，把 `assets/mcp/addin/PdmsBridgeAddin.cs` 的 `Start()` 调用复制进你的 `IAddin.Start()` 即可（命名空间按需改）。

### 步骤 C：启动 MCP 连接器
```bat
set PDMS_BRIDGE_DIR=C:\pdmsAgent\bridge
set PDMS_BRIDGE_TRANSPORT=tcp
node C:\Users\Nie\.workbuddy\skills\pdms-bridge\assets\mcp\server.js
```
（已在 `mcp.json` 注册，WorkBuddy 重启后会随客户端自动拉起。）

### 步骤 D：验证
在 WorkBuddy 里调用 `pdms_status`（或直接看 `server.js` 日志），应返回：
```json
{ "connected": true, "transport": "tcp", "host": "127.0.0.1", "port": 18753 }
```
随后即可用 `pdms_exec` / `pdms_query` / `pdms_create_drawing` / `pdms_iso_generate` 等工具驱动 PDMS。

## 6. 安全与降级（沿用既有护栏）
- 仅监听 `127.0.0.1`，无外网连接。
- 写通道有**黑名单**（`QUIT`/`SHUTDOWN`/`DELETE REGI`）+ `SET MDB` 禁用 + `openfile` 路径沙箱（必须在桥目录下）。
- PDMS 未加载插件 / 未启动时，`pdms_status` 返回 `connected:false`，MCP 进程不崩、不阻塞宿主（已实测）。
- 串行队列保证多 Agent 并发调用不串话（共享单结果文件）。

## 7. 待你确认 / 可选增强
1. **PML2 定时回调方法名**：档位 1 的 `AGENTBRIDGE.PML` 用了 `addTimedCallback`，请按本机 PML 版本核对（文档确认窗体有 callback，方法名可能略有差异）。
2. **插件注册方式（已查证本机）**：PDMS 12.1 的 Addin 清单是安装目录下的 `DesignAddins.xml` / `DraftAddins.xml` / `AdminAddins.xml` / `IsodraftAddins.xml`（均为 XML `<ArrayOfString>`，逐行列插件名）。`IAddin` 接口定义在 **`Aveva.ApplicationFramework.dll`**（命名空间 `Aveva.ApplicationFramework`），成员为 `Name`/`Description`（属性）+ `Start()`/`Stop()`（方法）——**注意**：不是 `Aveva.Pdms.Addins.dll`（本机无此文件），也不是 `.addin` 文件。部署时把 `PdmsBridge.dll` 放 PDMS 根目录，并把 `<string>PdmsBridge</string>` 加进对应 `*Addins.xml`。
3. **真实项目/MDB/账号**：档位 3 的 TTY 命令需替换 `<PROJECT> <USER>/<PASS> /<MDB>` 为你的实际值（PDMS 安装自带 `SAM`/`SAMPLE` 示例库可作首次试跑）。
